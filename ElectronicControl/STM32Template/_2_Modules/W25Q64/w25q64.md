# Module_W25Q64 开发文档

## 模块关系

```text
App
 └─ W25Q64 Module
     └─ SPI BSP
         └─ HAL SPI + CS GPIO
```

W25Q64 模块内部注册并保存 `SPIInstance`，App 不需要直接调用 `HAL_SPI_*`。

## SPI 配置

建议先使用以下配置：

```text
Mode:          Full-Duplex Master
Data Size:     8 bit
MSB First:     Yes
Clock Polarity: Low
Clock Phase:   1 Edge
NSS:           Software
```

CS 使用普通 GPIO 推挽输出，由 SPI BSP 在每次事务开始时拉低、结束时拉高。
## 初始化
 
先通过 CubeMX 配置 SPI 和 CS 引脚，然后调用：

```c
#include "w25q64.h"

W25Q64Data *flash = W25Q64Init(&hspi1, GPIOA, GPIO_PIN_4);
if (flash == NULL)
{
    // SPI 注册失败、内存不足或 JEDEC ID 不匹配
}
```

`W25Q64Init` 会完成以下工作：

1. 申请 `W25Q64Data`。
2. 以 `SPI_BLOCK_MODE` 注册 SPI BSP 实例。
3. 读取 JEDEC ID。
4. 校验 ID 是否为 `0xEF4017`。

## 接口

```c
int W25Q64ReadID(W25Q64Data *data, uint32_t *id);

int W25Q64Read(W25Q64Data *data, uint32_t address,
               uint8_t *buffer, uint32_t length);

int W25Q64Write(W25Q64Data *data, uint32_t address,
                const uint8_t *buffer, uint32_t length);

int W25Q64SectorErase(W25Q64Data *data, uint32_t address);
```

所有 `int` 接口统一返回：

```text
0  -> 成功
-1 -> 失败
```

## 读写与擦除

W25Q64 写入前必须保证目标区域已经擦除为 `0xFF`。推荐顺序：

```c
uint8_t tx_data[16] = {0};
uint8_t rx_data[16] = {0};

W25Q64SectorErase(flash, 0x000000);
W25Q64Write(flash, 0x000000, tx_data, sizeof(tx_data));
W25Q64Read(flash, 0x000000, rx_data, sizeof(rx_data));
```

说明：

- `W25Q64SectorErase` 会擦除 `address` 所在的整个 4KB 扇区。
- `W25Q64Write` 会自动按 256 字节页拆分，但不会自动擦除。
- 地址范围是 `0x000000～0x7FFFFF`。
- 擦除或写入期间模块会轮询 WIP 位并等待完成。


## 注意事项

1. W25Q64 使用阻塞式 SPI 操作，接口应在 FreeRTOS 任务上下文中调用。
2. 等待 WIP 清零时使用 `vTaskDelay`，调用前必须已经启动 FreeRTOS 调度器。
3. 模块内部的 `tx_buf` 和 `rx_buf` 由句柄持有，因此不要从多个任务同时访问同一个 `W25Q64Data`。
4. 不要把 W25Q64 命令和数据拆成两次 BSP 调用，当前 `SPITransmit` 和 `SPITransmitAndReceive` 每次调用都会释放 CS。
5. `W25Q64Data` 约 336 字节，使用 `pvPortMalloc` 分配；若同时创建较多模块，请检查 FreeRTOS 堆空间。
6. 如果 `W25Q64Init` 返回 `NULL`，优先检查 SPI 模式、CS 引脚、供电和 JEDEC ID。
